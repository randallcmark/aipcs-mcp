# Security policy

## Supported versions

`aipcs-mcp` is pre-1.0. Security fixes, when made, target the latest public
release only. There are no maintained backport branches or service-level
agreement.

## Reporting a vulnerability

Once this repository is public, use GitHub's **Report a vulnerability** flow
in the repository's Security tab. Do not open a public issue for a suspected
security issue, credential exposure, private record, database, export bundle,
or sensitive path.

The maintainer aims to acknowledge private reports within seven calendar days
when possible. This is an aspiration, not an SLA. Reports are handled on a
best-effort basis by the sole maintainer.

Before public visibility, private vulnerability reporting must be enabled in
the repository's GitHub security settings. GitHub Private Vulnerability
Reporting is the canonical reporting channel. If that route is unavailable,
reports may be sent to [security@indigo-blocks.uk](mailto:security@indigo-blocks.uk).

## Disclosure and fixes

The maintainer will assess a report, coordinate a fix where practical, and
use a GitHub Security Advisory for material confirmed vulnerabilities when
appropriate. Fixes and disclosure timing depend on severity, reproducibility,
affected users, and maintainer capacity. Please avoid public disclosure until
the report has been assessed.

See [the technical security and trust boundary](docs/security.md) for runtime
assumptions and non-goals.
